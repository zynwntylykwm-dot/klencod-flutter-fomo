# منارة | MANARA — منصة مزادات سيارات متكاملة

منصة مزادات سيارات احترافية بهوية تجارية مستقلة (MANARA Auto Auctions)، مستوحاة من تنظيم صفحات مزادات السيارات العالمية
ومحاكية لتجربتها الوظيفية بالكامل: تصفح، فلاتر متقدمة، تفاصيل لوت، مزايدة خادمية متزامنة، لوحة مستخدم، ولوحة إدارة.

> **تنبيه الشفافية:** بيانات اللوتات والصور والأسعار في هذه النسخة **تجريبية** لأغراض العرض. المزايدات تُسجَّل فعليًا في
> PostgreSQL عبر خدمات الخادم وتخضع لكل قواعد التحقق، لكن لا تتم عمليات دفع أو شحن أو تسليم حقيقية.

## 1) التقنيات

| الطبقة | التقنية |
| --- | --- |
| الواجهة | Next.js 16 (App Router) + React 19 + TypeScript + Tailwind CSS 4 |
| الخادم | Route Handlers تحت `src/app/api` (REST) |
| قاعدة البيانات | PostgreSQL + Drizzle ORM (`src/db/schema.ts`) |
| المصادقة | جلسات مخزّنة في قاعدة البيانات + كوكي HttpOnly + تشفير كلمات المرور بـ `scrypt` |
| التحقق من المدخلات | Zod في كل مسار كتابة (`src/lib/validation.ts`) |
| الأيقونات | lucide-react |
| الخط | Cairo (Google Fonts) مع واجهة RTL كاملة |

## 2) التشغيل

```bash
# 1. تثبيت الحزم (البيئة مُهيّأة مسبقًا في المنصة)
npm install

# 2. ضبط متغير البيئة في .env
DATABASE_URL=postgresql://postgres:postgres@127.0.0.1:5432/app_db

# 3. إنشاء الجداول
npx drizzle-kit push --config drizzle.config.json

# 4. تطوير / إنتاج
npm run dev
npm run build && npm run start
```

يتم **تعبئة البيانات التجريبية تلقائيًا** عند أول طلب (idempotent seed داخل `src/db/seed.ts`) عبر سجل `platform_meta`.
للتطبيق على قاعدة فارغة لا حاجة لأي خطوة يدوية بعد `drizzle-kit push`.

## 4) نظام المزايدة (خادمي فعلي)

`POST /api/vehicles/:id/bids` ينفذ داخل **معاملة قاعدة بيانات** مع `SELECT ... FOR UPDATE` على سجل اللوت:

1. التحقق من وجود اللوت وحالته `live`.
2. رفض المزايدة إذا انتهى وقت المزاد.
3. رفض أي مبلغ أقل من `أعلى مزايدة + الحد الأدنى للزيادة`.
4. رفض المزايدة إذا كان المستخدم هو المتصدر الحالي.
5. **مكافحة القنص:** عند المزايدة في آخر دقيقتين يُمدَّد وقت النهاية دقيقتين.
6. تسجيل المزايدة في جدول `bids` وتحديث `current_bid` و`bid_count` و`auction_end`.
7. إشعار المزايد السابق الذي تم تجاوزه (حسب تفضيلاته) وإشعار صاحب المزايدة الجديدة.

واجهة المزايدة تستعلم `GET /api/vehicles/:id/bids` كل ٥ ثوانٍ وتُظهر وقت آخر تحديث، مع إعادة مزامنة فورية بعد كل مزايدة.

### إغلاق المزادات وتحديد الفائز

`settleAuctions()` في `src/lib/auctions.ts` يُستدعى تلقائيًا عند تحميل صفحات العرض ونتائج البحث ونقاط المزايدة، ومتاح
يدويًا للمدير عبر `POST /api/admin/finalize`:

- تحويل اللوتات التي بدأ وقتها إلى `live`.
- إغلاق كل لوت انتهى وقته: أعلى مزايدة = الفائز (إذا استوفى السعر الاحتياطي)، وإلا يُغلق دون بيع.
- إصدار فاتورة تلقائية: سعر المطرقة + عمولة المشتري (٪ مع حد أدنى) + رسوم مستندات، حسب إعدادات المنصة.
- إشعار الفائز، وتحديث حالة المزاد الأم عند انتهائه.

| --- | --- | --- |
| `/api/health` | GET | فحص الاتصال بقاعدة البيانات |
| `/api/auth/register` / `login` / `logout` | POST | مصادقة وإدارة الجلسة |
| `/api/vehicles` | POST (admin) | إنشاء لوت |
| `/api/vehicles/[id]` | PATCH/DELETE (admin) | تعديل/حذف لوت |
| `/api/vehicles/[id]/bids` | GET/POST | قراءة الحالة والمزايدات / تسجيل مزايدة |
| `/api/watchlist` | POST | إضافة/إزالة من المفضلة |
| `/api/admin/upload` | POST (admin) | رفع صور اللوتات (multipart) |
| `/api/uploads/[file]` | GET | خدمة الصور المرفوعة |
| `/api/admin/auctions` + `/[id]` | POST/PATCH/DELETE | إدارة المزادات |
| `/api/admin/users/[id]` | PATCH | تغيير الدور/الحالة |
| `/api/admin/invoices/[id]` | PATCH | تغيير حالة الفاتورة |
| `/api/admin/notifications` | POST | إرسال إشعار |
| `/api/admin/settings` | PATCH | عمولات ورسوم المنصة |
| `/api/admin/finalize` | POST | إغلاق المزادات المنتهية الآن |
| `/api/invoices/[id]/pay` | POST | سداد تجريبي للفاتورة |

كل مسارات الإدارة محمية بـ `guardAdmin()` (جلسة + دور `admin`)، وكل عمليات الكتابة تُتحقق بـ Zod وتعيد رسائل خطأ عربية.

## 7) الأمان والصلاحيات

- كلمات المرور: `scrypt` مع ملح عشوائي لكل مستخدم، ولا تُعاد للواجهة أبدًا.
- الجلسات: رموز عشوائية ٢٥٦-بت في جدول `sessions` مع تاريخ انتهاء (٣٠ يومًا) وكوكي `HttpOnly` و`SameSite=Lax`.
- الحماية: `requireUser` / `requireAdmin` في صفحات الخادم، و`guardUser` / `guardAdmin` في واجهات API.
- إيقاف الحساب يمنع الدخول ويُبطل الجلسات عبر التحقق من الحالة عند كل طلب.
- المدخلات: تحقق مزدوج (واجهة + خادم)، قيود Zod للنطاقات، رفض الصور غير المسموحة أو الأكبر من 6MB، وحماية من اجتياز المسارات في مسار خدمة الصور.
- قاعدة البيانات: قيود مرجعية، فهرس فريد على البريد، فهرس فريد على (المستخدم، اللوت) للمفضلة.

## 8) قابلية التوسع والمراحل القادمة

- **الدفع:** استبدال المحاكاة في `/api/invoices/[id]/pay` بمزود حقيقي (Stripe/Tap/PayTabs) عبر webhook لتأكيد السداد.
- **الشحن:** إضافة جدول طلبات شحن وربط شركات شحن بواجهة خلفية مستقلة.
- **البث اللحظي:** استبدال الاستعلام الدوري بـ WebSocket/SSE أو Pusher عند النشر على بيئة تدعم الخدمات الدائمة.
- **البنية:** فصل الواجهة عن الخدمات (BFF/API مستقل) وتهيئة تخزين كائنات (S3) لصور اللوتات، وإضافة Rate limiting وAudit log.
- **الإشعارات:** إرسال بريد/SMS فعلي عبر مزود خارجي؛ الجدول والتفضيلات جاهزة.

## 9) قيود النسخة الحالية

- البيانات والصور تجريبية (Pexels وأصول مولّدة)، ولا تمثل لوتات حقيقية أو أسعارًا سوقية ملزمة.
- لا توجد بوابة دفع أو شحن فعلية؛ السداد يسجّل حالة الفاتورة فقط.
- التحديث اللحظي يعتمد على الاستعلام الدوري كل ٥ ثوانٍ مع مزامنة فورية بعد كل إجراء.
